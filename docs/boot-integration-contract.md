# Proposed boot factory contract (test-only, not wired)

`bootintegration/factory_test.go` describes **missing** `Build(Inputs) (servicehost.Runner, func() error, error)`. Inputs: signed raw bootstrap, caller-pinned Ed25519 bootstrap key, expected `lifecycle.Binding`, independently durable revision floor, installation-owned Windows journal path, explicit `ResolveJournalPath` adapter, `ResolveCredential` returning `tls.Certificate` plus `io.Closer`, trusted `Now() (time.Time,error)` and bounded `Collect(context.Context) (core.Posture,error)`. There is no `verified bool` bypass or preconstructed mutable `bootstrap.Verified` input. Production must call `bootstrap.Verify`, check its zero-value/validity, map the separately trusted path, `journal.Open` **existing only** with binding, validate `lifecycle.Recover` and trusted time before returning a runner; construct `runtime.Coordinator` using verified keys/timing and `transport.NewClient` using verified CA/origin and the checked certificate. `servicehost.Run` takes the returned runner as its factory result. `Close` owns all opened journal and credential resources, including partial acquisition failures, and must not discard the original error. Stop is cooperative, not a hard kill.

The fixture uses `t.TempDir()` for the real bbolt journal. Its **test-only** path adapter maps an exact, canonical Windows `C:\ProgramData\eGuardNAC\state.db` installation path to that Linux temporary file; this is not proof that a Linux temp path is acceptable bootstrap config or that Windows ACL/reparse/ownership checks have happened. A production Windows adapter must independently enforce installed path, ACL, anti-reparse and ownership, and the caller must persist a rollback-protected revision floor and establish trusted time. A test credential resolver returns ephemeral in-memory Ed25519 client cert/key; production LocalMachine/CNG provisioning and private-key protection are not supplied by these tests.

The success test requires raw signed bootstrap, signed initial lifecycle acceptance committed to an existing journal, CA/SAN-checked actual loopback HTTPS/mTLS receipt, and servicehost runner use. Failure tests require no collection or transport, no journal creation, and resource release. Server ACK proves evidence receipt only, not assignment or authorization. **Windows runtime NOT RUN**. No service factory enabled, enrollment, installer, or release claim.
