# Signed boot configuration — proposed contract, NOT implemented

`bootstrap/config_test.go` specifies `Verify(raw, pinned ed25519.PublicKey, expected lifecycle.Binding, durableFloor uint64, expectedJournalPath string) (Verified, error)`. This API is absent. An envelope carries version, base64 raw payload and an Ed25519 signature over `"eguard-nac-boot-config/v1\x00" || rawPayload`. Signature verification must use the **caller-supplied** pinned public key, never a key embedded in the blob; use strict parsing, bounded input and exact fields at every JSON object level. Reject duplicate/unknown/null/trailing fields, malformed base64, invalid signatures/keys, oversized data, invalid CA/key/fingerprint, cross-binding and revision below the caller-supplied durable floor. The signature authenticates bytes, not time, disk durability or an installer.

Payload v1 fields: `version`, `purpose`, `issuer`, `device_id`, `tenant_id`, `site_id`, `enrollment_id`, `revision`, `https_origin`, `server_ca_der_b64`, `lifecycle_keys` (key ID → Ed25519 public key), `machine_cert_sha256` (leaf DER fingerprint), `journal_path`, `interval_seconds`, `backoff_seconds`, `collect_timeout_seconds`, `send_timeout_seconds`. Timing must be positive and bounded. HTTPS origin has no credentials, path, query or fragment; transport adds only `/v1/nac/posture`. Journal path must match an independently provisioned absolute installation-owned path; no config-provided alternate path or implicit creation on service boot. `Verified` must expose only immutable values or defensive copies; consumers construct `transport.Config`, `runtime.Coordinator` and `journal.Open` dependencies themselves. Fingerprint is for locating/checking a machine certificate, **not** its private key, enrollment proof, or TLS authorization. No secrets in config.

The caller owns trusted bootstrap pin provisioning/rotation and durable rollback-protected revision-floor storage, plus secure file ownership/ACL checks and trusted clock/rollback evidence. A signed config alone does not grant lifecycle authority, establish current time, prove certificate possession or authorize collection. Lifecycle keys must still validate journal history via `lifecycle.Recover`; runtime must enforce signed state and deadlines. No fallback to fixture trust, `time.Now`, self-signed pins or `journal.Create` on boot failure. The proposed verifier is a prerequisite for a factory, not an operational factory.

Linux tests can validate byte-level contract and API invariants only. Intended Windows path additionally requires ACL-protected ProgramData, existing journal binding, LocalMachine CNG non-exportable signer, trusted clock, verified service binary and actual SCM/Job Object/CNG runtime validation on an authorized disposable VM. **Windows runtime NOT RUN**. No installer, enrollment delivery, server route, production signing root, or live transport is established here.
