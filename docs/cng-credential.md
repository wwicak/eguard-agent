# Kredensial CNG mesin

`cngcred.Resolve([32]byte)` cocok langsung terhadap SHA-256 DER sertifikat di `LocalMachine\MY` (bukan subject/serial). Store dibuka existing-only dan read-only; duplikat ditolak. Kunci diambil dengan `CryptAcquireCertificatePrivateKey` menggunakan `ONLY_NCRYPT|SILENT|COMPARE_KEY`; export policy CNG wajib tersedia dan semua bit izin ekspor/arsip harus nol. Tidak ada ekspor private key. `tls.Certificate.PrivateKey` adalah `crypto.Signer` yang memakai `NCryptSignHash`; ECDSA P-256/P-384 raw menjadi ASN.1 DER, RSA mendukung PKCS#1 v1.5 dan PSS. Pemanggil **wajib** menutup `io.Closer` sesudah seluruh penggunaan TLS selesai; pemanggilan Sign sesudah Close ditolak.

Contoh wiring oleh pemilik boot factory: `Inputs.ResolveCredential = cngcred.Resolve`. Package ini tidak membuat sertifikat/kunci, tidak mengubah store, dan tidak memverifikasi trust server atau lifecycle. Provisioning harus memasang sertifikat ClientAuth dan kunci CNG non-exportable ke mesin serta memberikan akses key kepada akun service tanpa membuka hak ekspor. Tidak ada fallback ke CurrentUser/CSP atau prompt UI.

Pengujian Windows opt-in `EGUARD_NAC_CNG_ITEST=1 EGUARD_NAC_CNG_FP=<64 hex>` memerlukan fingerprint DER leaf yang telah dibuat terpisah di `LocalMachine\MY` (misalnya operator memakai `New-SelfSignedCertificate` dengan kunci non-exportable). Test memverifikasi signature terhadap public key leaf, export policy, dan penolakan Sign setelah Close. Tidak ada handshake TLS dalam test ini. Test Linux untuk konversi dan fingerprint bukan bukti runtime CNG/ACL Windows. Query policy hanya membuktikan izin ekspor yang dilaporkan provider, bukan pembuktian hardware atau ketahanan terhadap administrator/SYSTEM. Store/certificate mutasi paralel saat enumerasi tidak diberi snapshot atomik; integrasi perlu diuji di VM.
