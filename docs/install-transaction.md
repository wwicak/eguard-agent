# Transaksi instalasi SCM (slice mekanis, BELUM TERPASANG)

`installtransaction.Run` adalah lapisan **sesudah admission**. Caller keamanan yang belum tersedia wajib memverifikasi otorisasi administrator, identitas paket dan binary, trust bootstrap, kredensial, lifecycle bertanda tangan, pilihan AntiTamper ON/OFF dan readiness operasional factory service **sebelum** memanggilnya. Parameter fungsi bukan bukti admission; contoh fixture test tidak boleh dijadikan otorisasi. NSIS masih inspection-only; paket ini tidak dihubungkan ke installer maupun service main. Tanpa factory produksi yang valid, SCM.Ready selalu gagal, bukan melaporkan sukses hanya karena SCM Running. Tidak ada provisioning/ACL/cleanup filesystem atau auth di paket ini.

Adapter SCM Windows menggunakan `mgr.Connect`, `OpenService`, `Config`, `Query`, `CreateService`, `Start`, `Control(Stop)` dan `Delete` dari x/sys; tidak menjalankan shell. Nama service selalu `eGuardNAC`, path binary selalu `C:\Program Files\eGuard NAC\eguard-nac-service.exe`; konfigurasi yang berbeda ditolak (termasuk service asing). Existing *meskipun cocok* ditolak: upgrade/repair membutuhkan restore versi lama yang aman dan belum diimplementasikan. Tidak menyentuh EDR. Binary path fixed belum membuktikan binary aman/owned; caller harus melakukan pinning/signature, pemeriksaan reparse/path/ACL dan provisioning terpisah sebelum memanggil adapter. Adapter tidak membuat file dan tidak mengubah ACL.

CreateService yang berhasil pada adapter ini adalah satu-satunya bukti ownership transaksi. Kegagalan sesudah create mencoba stop → poll stopped → delete, hanya untuk service baru dengan konfigurasi yang tetap cocok. Error rollback digabung dengan error asli. Timeout rollback 5 detik; apabila stop/delete gagal, service dapat tertinggal dan memerlukan investigasi administrator, bukan penghapusan paksa. Bila SCM melaporkan Running dan adapter Ready memiliki evidence operasional sah, transaksi selesai tanpa mengubah resource lain. Poll memakai context dan interval positif; operasi SCM serta Ready yang macet tidak dapat diinterupsi paksa oleh Go context: integrasi produksi wajib membatasi panggilan adapter/callback dan menguji Windows SCM. Rollback setelah pembatalan memakai context baru terbatas agar cleanup masih dapat dicoba.

Linux fake-adapter tests hanya membuktikan state machine, bukan runtime Windows. Windows cross-build membuktikan pemakaian API terkompilasi, bukan install, UAC, snapshot, signing atau readback SCM. Runtime adapter Windows **NOT RUN** sampai Windows 11 disposable snapshot berizin; WIN PNUP saat ini Windows 10, hanya akses read-only. UI tetap approval-gated, tanpa arbitrary command/EDR/network enforcement. Jangan klaim installer fungsional atau release.
