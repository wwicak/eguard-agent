# Journal v3 mekanis — riwayat lifecycle untuk verifikasi pemulihan

`journal.Create` hanya untuk bootstrap enrollment terverifikasi dan file baru (`O_EXCL`); `Open` hanya untuk existing. Schema/bucket `journal-v3` menolak v1/v2/tidak dikenal tanpa migrasi/reset otomatis; belum ada deployed journals. bbolt v1.4.3 (MIT) melakukan transaksi fsync default dan writer lock lintas proses. `AcceptLifecycle` dan `AcceptCleanup` adalah primitive storage internal, **bukan** verifier atau izin cleanup. Caller WAJIB memverifikasi original signed envelope, issuer/key/purpose/action, binding device/tenant/site/enrollment, revision/nonce, validity dan clock terpercaya sebelum transaksi. `BeforeCommit` hanya fault injection test.

`Snapshot.History []AcceptedRecord` menyimpan semua envelope lifecycle yang diterima selama enrollment, mulai dari anchor awal, dalam urutan revision yang meningkat ketat dan timestamp penerimaan nondecreasing. `Snapshot.Lifecycle` tetap record terakhir dan harus sama persis dengan elemen terakhir History (revision, timestamp, byte envelope). Append history, latest, revision dan nonce terjadi dalam transaksi `ExpectedRevision` CAS yang sama; cleanup intent tidak mengubah history. `Read` menghasilkan salinan independen. History maksimum **32** entry (tidak pernah evict anchor), masing-masing envelope <=64 KiB dan total JSON record <=256 KiB; saat penuh transaksi lifecycle baru gagal tanpa perubahan. Nonce maksimum 4096 dan ID maksimum 128 ASCII printable non-spasi. Tidak ada rotasi otomatis; exhaustion memerlukan protokol resmi, bukan menghapus anchor atau membuka ulang state baru.

Cleanup authorization mempertahankan bytes, revision lifecycle yang terkait, intent ID, timestamp penerimaan caller, dan enrollment binding. `MarkCleanupDone(intentID,enrollment)` hanya untuk intent dan enrollment tepat, idempotent untuk intent sama. Pending/done terminal. Saat boot, parent harus reverify **seluruh** history cryptographically, menguji kontinuitas/transisi/action awal, baru mempertimbangkan record cleanup committed. Storage cuma mengecek urutan revision/timestamp dan byte equality, **tidak** menjamin signature, aksi, clock trust, absence of revision gaps, atau keaslian chain. AcceptedAt disuplai caller dan bukan bukti waktu tersendiri. History expired bukan grant baru; verifikasi historis berbeda dari penerimaan baru.

Tidak ada service yang memakai journal, tidak ada OS cleanup aktif. Disk biasa tidak melindungi dari rollback admin/offline. Windows ACL/CNG, trusted bootstrap, boot verifier chain, signed transport/enrollment, expiry offline, crash/power-loss VM dan installer resmi masih belum ada. Windows runtime **NOT RUN**; NSIS inspection-only `TEST-UNSIGNED`.
