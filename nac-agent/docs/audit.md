# Audit keamanan dan integrasi (parsial)

- Sumber read-only `eguard-agent-v15-av` mempunyai workspace Rust 13 crates, `agent-core/lifecycle/enrollment.rs`, `uninstall_auth.rs`, `platform-windows/compliance/{defender,firewall}.rs`, grpc-client; juga WFP, response actions, eBPF dan telemetry EDR. Lisensi workspace GPL-2.0-or-later. Tidak ada kode atau asset sumber yang disalin; atribusi referensi tetap diberikan. Dependency NAC: Go stdlib; `golang.org/x/sys` v0.47.0 (BSD-3-Clause); `github.com/go-ole/go-ole` v1.3.0 (MIT); `github.com/StackExchange/wmi` v1.2.1 (MIT). Inventory aktual `go list -m all`, license asli tersedia di module cache dan notice `docs/third-party-notices.md`. Tidak ada kode sumber EDR yang disalin; **tidak** ada dependency EDR, shell executor atau driver. Pilihan Go menyimpang dari usulan Rust: toolchain Rust tidak tersedia lokal pada slice pertama, Go 1.26 + native x/sys/COM memungkinkan cross-compile/test cepat; tradeoff WMI COM lambat/tidak bisa dibatalkan dan integrasi Windows masih perlu VM. Ini bukan bukti Go lebih aman ataupun Windows runtime teruji.
- Backend worktree pada commit `5982dc15ec`: `go/agent/server/enrollment.go` POST `/api/v1/endpoint/enroll` menerima CSR/token/tenant dan mengembalikan sertifikat, initial_policy/rules. Belum ada kontrak NAC signed mode/expiry/assignment serta auth uninstall end-to-end; tidak aman memakai response EDR sebagai grant NAC. Backend tidak diubah. Perlu telaah issuer, token single-use, tenant binding, persistence/audit, mTLS dan RBAC sebelum route NAC baru. Jangan percaya `agent_id`, tenant, MAC, header identitas atau policy dari caller saja. Hanya server menetapkan masa berlaku berdasar aktivasi pertama.
- Core `Grant` menggunakan Ed25519 library standard Go, JSON canonical via `encoding/json` pada struct tetap, signature mencakup device/tenant/site/revision/action/nonce/deadline. Ini **belum wire contract**: sebelum integrasi definisikan versi protokol dan byte encoding antar bahasa, signed server key provisioning/pinning, authenticated transport, persisted monotonic revision+nonce atomik dengan ACL, rollback handling dan clock monotonic. State kini in-memory saja, tidak boleh dipakai sebagai izin uninstall nyata.
- Collector kini punya acquisition khusus Windows: NetGetJoinInformation, GetAdaptersAddresses, Win32_NetworkAdapter PhysicalAdapter, GetIpForwardTable2(AF_UNSPEC) default IPv4/IPv6 dan RtlGetVersion OS build, COM INetFwPolicy2 FirewallEnabled per profile, SecurityCenter2 AntiVirusProduct, WMI MSFT_MpComputerStatus; seluruhnya read-only dan terpisah dari normalisasi unit-test Linux. Adapter physical hanya bila PnP PhysicalAdapter benar dan nama tidak konflik; virtual berdasarkan bukti PnP/tunnel/nama; lainnya unknown. ActiveRoute true/route_status=yes hanya bila route IPv4/IPv6 default cocok nonzero index; false/route_status=unknown **bukan** bukti tidak ada route. Kegagalan API/table melebihi limit => Unknown. Domain match tidak mungkin Yes tanpa expected domain signed; Windows service selalu memasok kosong. Vendor SecurityCenter2 state opaque dan Defender pasif tidak membuktikan vendor lain sehat. WMI/COM gagal -> Unknown dengan reason, tanpa pemalsuan. Service sekarang menjalankan satu proses lokal dengan executable sendiri + verb tetap (bukan shell/API arbitrary), stdout maksimum 256 KiB, context deadline 12 detik, Windows Job Object kill-on-close dan ACTIVE_PROCESS=1; Linux test menguji timeout, output malformed/oversize, race dan process group cleanup. WMI internal yang menggantung di child dapat di-kill oleh parent. Child menunggu byte gate dari anonymous inherited stdin pipe (deadline 5 detik) sebelum memulai collector, sehingga jendela Start→AssignProcessToJobObject tidak menjalankan kerja koleksi; parent crash/EOF/invalid byte => child keluar. Assignment gagal => parent menutup gate, child di-kill dan fail closed. Tidak ada bukti Windows Job Object bekerja sampai VM dijalankan; service tidak boleh diinstal sebelum ACL/signing dan uji VM. Parent menolak output lama/timestamp future/TTL di luar batas serta output malformed; tidak mempercayai raw evidence bila gagal, tidak mencetak raw identitas. Kanal stdout adalah child lokal dari binary sama, **bukan IPC terautentikasi terhadap admin lokal**: tanpa signed binary dan ACL instalasi yang benar, user lokal yang bisa mengganti binary dapat memalsukan evidence. Windows gate/Job assignment dan exit saat parent crash masih perlu pengujian VM sebelum dipakai. Stdin anonymous pipe bukan authenticasi kriptografis admin lokal; hanya handle parent yang membawa byte gate. Event log hanya ringkasan tanpa identitas; raw snapshot dari nac-inspect berisi data sensitif, khusus VM. Belum ada verifikasi Windows runtime. Evidence TTL diuji. Tidak mengakses proses, software inventory, browser, driver, atau device jaringan.
- Threat model: user biasa dibatasi ACL Windows resmi setelah desain installer; admin/SYSTEM/offline disk dapat mengubah state dan menghapus aplikasi; mTLS tidak mengotentikasi posture dari host yang dikuasai admin. Saat ini ACL, non-exportable CNG credential, key pin, audit, replay store durable, rotasi/revoke, signed update, cleanup/recovery resmi, anti-rollback clock, heartbeat dan outage policy **belum ada**. Maka service tidak mengirim/menerima data, tidak menginstal, tidak menjalankan aksi cleanup. Tidak ada network enforcement.
- Installer inspection-only unsigned **bukan deliverable installer**: menyalin payload ke TEMP saat dijalankan, tanpa persistence; tidak diklaim sebagai installer target. Jangan distribusikan sebagai release. Tidak ada Windows VM/runner/signing capability terverifikasi; Linux cross-build + NSIS bukan validasi Windows. Verifikasi service SCM, user standard ACL, expiry reboot, official recovery, signed uninstall, UAC, clean upgrade/downgrade dan coexist EDR di VM snapshot sebelum installer fungsional. Penghapusan folder TEMP inspeksi dilakukan manual; tidak mengubah service/EDR.
- Desain integrasi berikut: endpoint NAC terpisah, identitas certificate-bound, signed grants versioned, DB constraint single-use enrollment and replay durable, admin RBAC+audit, posture provenance; server authoritative expiry even offline agent, TTL evidence terpisah dari grant; observe-only evaluation dahulu. Tidak ada report/UI/network write pada slice ini.
