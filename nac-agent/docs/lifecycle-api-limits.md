# Batas API lifecycle saat ini (review lokal)

`lifecycle.Accept(store, envelope, keys, binding, trustedNow)` menerima waktu eksplisit dari caller; tidak memperoleh bukti waktu tepercaya sendiri. `Recover(store, keys, binding)` memverifikasi ulang record terakhir pada `AcceptedAt` tersimpan, bukan memeriksa kelayakan akses saat ini. `Observation.State == "active"` menyatakan status lifecycle historis, **bukan** keputusan NAC untuk akses jaringan atau bukti Temporary belum kedaluwarsa. `cleanup_pending` hanyalah intent tercatat; tidak menjalankan cleanup OS. Tidak ada service/transport yang memakai API ini.

Journal v2 menyimpan envelope lifecycle terakhir dan cleanup secara terpisah, revision/nonce serta intent terkait; tidak menyimpan rantai seluruh transisi. Pemeriksaan saat `Accept` memvalidasi transisi dari state terakhir dan CAS dalam transaksi journal, tetapi `Recover` tidak dapat membuktikan semua transisi historis hanya dari record terakhir. Saat rotasi signer, trust policy untuk signer historis perlu ditetapkan pada lapisan provisioning; `Recover` hanya memerlukan key untuk envelope yang masih tersimpan. Map dan byte public key milik caller harus dipasok dari trust bootstrap yang terverifikasi dan tidak dimutasi saat pemanggilan. `Accept` menyalin byte envelope sebelum menyimpan, namun hasilnya dibaca ulang sesudah commit; observasi yang dikembalikan tidak boleh diasumsikan snapshot atomik yang terikat pada transaksi pemanggil jika ada writer lain. Hal itu belum diuji secara deterministik.

`AcceptedAt` adalah input journal yang tidak membuktikan waktu server atau ketahanan rollback. Record salah waktu di luar jendela grant ditolak saat recovery, tetapi local admin/offline disk rollback tidak dijanjikan dapat dicegah. Tidak ada eligibility akses jaringan, clock proof, enforcement, auto-expiry/cleanup Temporary, Windows ACL/CNG runtime, ataupun validasi installer di sini. Installer saat ini inspection-only TEST-UNSIGNED; Windows runtime **NOT RUN**.
