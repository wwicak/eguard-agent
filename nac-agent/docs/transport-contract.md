# Transport NAC HTTPS/mTLS — submission idempotent mekanis

`NewClient(Config{BaseURL, RootCAs, ClientCertificate, Timeout})` menghasilkan klien dengan endpoint tetap POST `/v1/nac/posture`. `PreparePosture(core.Posture) (Submission,error)` mengambil snapshot JSON saat dipanggil (maksimum 64 KiB), ID permintaan 128-bit dari `crypto/rand` yang dikodekan menjadi 32 karakter heksadesimal lowercase, dan menyimpan keduanya dalam field privat yang tak dapat diubah caller eksternal. `Client.SendSubmission(ctx, submission)` mengirim **byte JSON dan `Idempotency-Key` yang identik** pada setiap pemanggilan dengan submission yang sama; nol atau submission internal yang korup/forged ditolak sebelum dispatch. Pengiriman serentak dengan nilai submission yang sama memakai reader terpisah per request. Tidak ada retry otomatis atau antrean disk. `SendPosture(ctx,p)` hanya wrapper yang memanggil PreparePosture sekali lalu SendSubmission sekali; pemanggilan wrapper berikutnya adalah **submission baru dengan ID berbeda**, bukan retry aman dari pengiriman sebelumnya. Retry setelah restart memerlukan persistensi submission yang belum tersedia.

TLS memakai HTTPS, trust CA eksplisit, cert client terprovisi, hostname/SAN diverifikasi tanpa `InsecureSkipVerify`, origin tetap tanpa redirect; tolak URL dengan userinfo/query/fragment/path. Timeout/context cancellation, batas respons 4096 byte dan header, status tepat 200, content type JSON dan acknowledgment tepat `{"accepted":true}` tetap dipertahankan. ACK hanya penerimaan evidence, bukan assignment atau keputusan akses. Backend harus mengikat identitas ke client certificate/authoritative mapping dan menerapkan idempotency sendiri. Klien tidak memverifikasi bahwa backend menyimpan transaksi atomik; test di repo agent hanya loopback TLS sintetis.

Belum terhubung service, enrollment, backend E2E, CNG/credential aman, retry/disk queue maupun runtime Windows. Tidak ada akses live; installer tetap inspection-only TEST-UNSIGNED.
